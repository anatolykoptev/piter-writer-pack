# piter-writer

The invariants for producing validator-clean city-guide articles on **piter.now** through the go-wp MCP pipeline, for a remote writer agent with ONLY MCP access — no SSH, no server filesystem, no WP admin. The per-task step-by-step recipes are the **bundled go-wp skills** (`create-article`, `update-article`, `fix-article`, `update-facts`, `update-single`, `news-pipeline`, `create-events`, `maintenance`) shipped next to this file; this skill holds what holds REGARDLESS of which recipe runs. **A PRIME DIRECTIVE here WINS on conflict.** You are an editor + researcher, not a code agent.

## Access map (everything goes through the go-wp MCP — there is no SSH)
| Thing | Where | How to touch it |
|---|---|---|
| go-wp MCP tools | `https://mcp.krolik.run/wp/mcp` | call after your agent's MCP tool discovery (`mcp_list_tools` / ToolSearch / equivalent) |
| pipeline temp files (`decompiled-places-ID.jsonl`, `collection-ID.json`, `enrich-*.json`, `places-ID.jsonl`, `*-compiled.json`) | inside go-wp at `/tmp/go-wp/{project}/` | `wp_temp action=read file=<name> project=piter` — NEVER reachable by filesystem |
| recipe skills | bundled: `../<recipe>/SKILL.md` next to this file | read locally, fresh each run |
| `_common.md` (content rules + JSONL bible) | bundled inside every recipe dir | read EVERY run |
| `templates.md` + `podborka-editorial` (lead/intro doctrine) | bundled in every recipe dir / `../podborka-editorial/SKILL.md` | read before composing |
| images | `wp_image action=resolve_candidates` → review `thumbs/` via `wp_temp action=read` + your own vision/download of the live candidate URLs | selection BEFORE upload, per Directive 3 |
| live-page check | the public URL itself | fetch/render `https://piter.now/<slug>` with whatever HTTP/browser tool YOUR agent has — you have no server-side browser |
| WP-CLI, nginx, mu-plugins, imgproxy, host files | NOT available to you | **never attempt — flag to the operator** in the report |

Anything a recipe tells you to reach over `ssh` is operator-side infrastructure. Substitute the `wp_temp`/`wp_*` MCP equivalent above; if none exists, that step is not yours — flag it and continue with what the pipeline defines.

## Your authority boundary (server-enforced, not etiquette)
Your token is a **writer** identity scoped to `project=piter`. The server rejects — regardless of how politely a recipe asks — publishing/live mutation of published posts, `wp_cli`, workflow steps marked `run_as: operator`, `go-live` approval, and every project other than `piter`. A `denied` response is the system working correctly: do not retry, do not look for another way to reach the same effect, report it.

The `podborka-editorial` skill is the single source of truth for the lead/intro/brief — never write the opening from memory or from any restatement.

## Routing — pick the bundled skill by content_type (`wp_scan`/`wp_audit_article` classify)
`place-listicle` → `update-article` (full) / `fix-article` (targeted) · `fact-listicle` → `update-facts` · `historical-date`|`place-review` → `update-single` (Gutenberg blocks directly, NOT JSONL) · `news` → `news-pipeline` · new article → `create-article` (via `wf_create` template `create-collection`) · cross-article (link/tag/SEO) → `maintenance` · `advertorial` → **skip** (sponsored, don't auto-touch). "Full refresh"→update-article; "just fix validator errors"→fix-article; new collection→create-article.

## Pre-build DEDUP-OR-UPDATE gate (run FIRST on any "create", before research)
A topic can be a section inside a broader page, so a title search alone isn't enough. Check BOTH ways: `wp_post action=list search=<head-query>` (title) AND a content grep for the head-query across collection posts (esp. many-`h3` ones); run `wp_dedup_batch` if available. Decide + report the call: **none** → build fresh · **same intent + current** → STOP, report «уже покрыто #ID» · **same intent + stale** (legacy format / dead links / outdated prices) → UPDATE that #ID in place · **different angle** (geo/price-tier/audience) → build NEW + interlink. One head-query + one intent = one page; torn → prefer UPDATE; always surface the decision.

## Pipeline shape (place-listicle, the common case — follow the bundled skill's exact tool calls)
1. **SELECT+PRD** — `wp_prd action=optimize post_id=ID`→`prd-ID.json` (work plan); `wp_format_spec category_id=CAT` — read `content_rules.guidelines`. No post_id → `wp_scan action=refresh` then `action=next`.
2. **AUDIT** — `wp_audit_article post_id=ID`; `wp_post action=get decompile=true`→`collection-ID.json` (meta) + `decompiled-places-ID.jsonl` (current places); `wp_seo action=get`. Read the decompiled JSONL via `wp_temp action=read` — you write a PARTIAL update.
3. **RESEARCH (per place, mandatory)** — `wp_research_get` → `wp_enrich mode=places data=[{name,url}]` → if insufficient use your own agent's web search/fetch on the official site. Verify open-now / moved / renamed / closed / current price+schedule+phone+address. Closed → research «альтернатива Name City», research the replacement, reuse the rank. `wp_research_save` all 6 fields.
4. **IMAGES (per place)** — Directive 3; every image needs a concrete `image_caption` (≤90 chars).
5. **COMPOSE** — write `places-ID.jsonl` via `wp_temp` (one block/call, partial-update semantics; Directive 5 + gates in Directive 2).
6. **VALIDATE** — `wp_temp action=compile` → `wp_render_blocks places_file=… meta_file=… validate=true validate_level=lenient save_to=…collection-ID-compiled.json` (`strict` for brand-new; `lenient` for partial). Errors → `wp_temp action=update rank=N` → recompile → re-render. **Never hand over a draft with errors.**
7. **DRAFT + AUDIT LOOP** — `wp_post action=update blocks_file=…compiled.json` (draft only — live posts are server-denied to you) → `wp_seo action=set` (title 50-60 char w/ keyword, desc 150-160 w/ CTA verb) → `wp_post action=update excerpt="≤150 char, сок-first"` → `wp_check_style text="<composed RU>"` (NOT `post_id=` — Directive 4 guard) → `wp_audit_article` → **fix → recompile → re-update → re-audit until 0 errors** → `wp_image action=set_featured` + `wp_manage_tags assign_date_tags`+`assign_by_keywords`. `wp_flush_cache` on a draft is a no-op you may skip.
8. **HANDOFF (your terminal state, not a pause)** — emit the reporting contract below with the draft post_id + workflow_id. Publishing (`go-live` → publish→flush→live-verify) is the OPERATOR's step — the server will not let you do it. Never claim or imply the post is live.

## PRIME DIRECTIVES (non-negotiable; win over any recipe)
**1 — Anti-fabrication (cardinal).** Every fact (address/phone/website/price/schedule/hours/specialty/"24-7"/"has MRI"/named-staff) comes from `wp_enrich`/your own research/official sites. Never invent, never expand a caption into a fact, never trust the existing article's data — re-confirm every value THIS run. **Unverified → leave the field empty and flag it. Empty beats invented.** Suspicious enrich match (wrong name/city) → don't use, flag, re-research or replace. Shape-check every enrich value: a `price` not `<number> ₽/р` isn't a price; an aggregator label (2GIS/Yandex/zoon) isn't the name; `hours`→must become `schedule`; a placeholder `website` (`уточняется`) isn't a domain → any shape-fail = UNCONFIRMED. Distrust aggregator/call-tracking contacts (8800; a Moscow 495/499/916 on a СПб place) → confirm against the venue's OWN site. Record replacements in `wp_research_save facts_rejected={…}` + report. **Provenance checkable:** every contact/price/schedule/specialty needs a `facts_used` entry with the literal value AND where seen; can't quote where → not sourced → leave empty. **Same-name entity guard: one card = ONE entity = ONE official site** — take EVERY field from that one site; never assert an affiliation or building/history detail not on it (default = no affiliation claim); the phone must be a `tel:` on that same site; never merge attributes across same-named orgs.
**2 — Validation gates (authority = the validator constants).** *Paragraphs:* 2-3 per place, 150-350 chars (no spaces); a 4th only for a load-bearing fact that can't condense; repeating info-block data in prose = hard defect; FORBIDDEN in paragraphs: addresses/phones/websites/schedule/exact info-block prices (context prices "от 180 ₽" OK). WHAT a paragraph contains is in `templates.md` — read before composing. *Info = the `pn/info-grid` block, never prose* (legacy `<strong>Адрес:</strong>` paragraphs audit clean but render no block — convert on any touch): mapped labels (`info_key_map`: Адрес→address, Телефон→phone, Сайт→website, Режим/Часы/График→schedule, Цена/Стоимость→price)→typed fields; unmapped DIRECTORY-FACT labels stay IN the grid as `{type:custom,label,value}` rows (SHORT labels) — do NOT dump into features; features = PROSE differentiators, NOT scannable facts; on any legacy touch preserve EVERY field; **re-verify directory facts against the LIVE source on any touch**. *CTA tiers are a PAID product distinction — never change form factor:* simple CTA = plain `wp:button`; premium `foxiz-elements/cta`: meaningful `heading`, `headingHTMLTag:"h3"`, `description` a real RU line NEVER absent (empty → theme injects an English placeholder), `imageURL`, buttons primary `isButtonBorder:false`/socials `true`, all `isNewTab`+`noFollow`. *CTA copy = a conversion instrument* (RU editorial register, concrete-not-loud; URL+UTM advertiser-supplied).
**3 — Image discipline (QC mandatory; selection BEFORE upload, on thumbnails; `_common.md` owns exact calls).** (1) `wp_image action=resolve_candidates place_name=… query=… website=<official> max_results=8` (downloads+thumbnails, writes `manifest.json`, no upload) → (2) review thumbnails (`thumbs/{idx}.jpg` — read via `wp_temp action=read` for paths, then fetch the images with your own tooling or a cheap subagent) → (3) `wp_image action=upload_selected slug=… selected=[indices] alt_text=…` (first=cover). **Reject** any thumbnail that is a logo/banner/icon/cartoon, watermark-heavy/low-quality, an error/placeholder graphic, blank-grey, a portrait, the WRONG venue, or byte-identical to another. Source priority: official-site **og:image FIRST** (always pass `website=`) → Yandex Maps → VK → Pexels (landscape, last resort). `available_count=0` → retry different query / drop website param; exhausted → leave `image_id` empty + flag. **Caption may NAME the venue only if the photo is provably its OWN** (og:image or reverse-search to its own site); illustrative stock → caption describes the activity NEUTRALLY.
**4 — RU hygiene + humanizer (write-time, first draft).** Compose clean Russian on the FIRST draft. Apply the six `_common.md` hygiene rules + humanizer (vary sentence length, ≤1 em-dash/para, no rule-of-three, no inflated symbolism, no vague attributions, no filler). **Tool-signature guard:** `wp_check_style` takes `text=` (required) NOT `post_id=`; check LIVE published post with `wp_check_anglicisms post_id=ID`.
**5 — JSONL via `wp_temp` only (sandbox discipline).** Every JSONL block through `wp_temp` (write, then `append=true`), one JSON object/call — no multi-line blobs, no loops. Point-fix one place with `wp_temp action=update rank=N file=… content='{"paragraphs":[…]}'`, never delete-and-rewrite the whole file. Partial-update merge: omitted string=inherit; `nil` array=inherit, `[]`=clear; `nil` map=inherit, `{}`=clear, `{"k":"v"}`=merge.
**6 — Audit loop closes at zero.** After the draft update `wp_audit_article` must return 0 errors; else read errors → fix → recompile → re-update → re-audit until clean. Never report "done" with open errors.
**7 — Internal cross-links (`extra-info-block`) — SEO-useful, never repeated.** Render as `<p class="extra-info-block">`, once each. Each a written sentence with descriptive keyword-bearing anchor text, never a bare URL. Supply 3-5 DISTINCT sibling collections forming the topic cluster, each a DISTINCT published URL. Complement (don't mirror) the auto foxiz related-by-tag widget. Link only to published collections verified to resolve (200 not 404); none → omit.
**8 — Warmth (lead with the reader's stake, not the spec sheet).** Frame each fact through what the reader fears/hopes, then anchor in the number/name. Warmth is a REPORTING act — name the reader's situation in concrete checkable words, never adjectives about virtue; never promise a RESULT you can't verify. Opening craft is in `podborka-editorial`; the rest in `_common.md` → Warmth + Paragraphs.

## Legacy-article trap (this site)
Many piter.now articles lost paragraphs/features/CTAs in a migration (why the validator flags them). Rebuilding: `wp_render_blocks` may re-insert ad blocks / alter CTAs vs the live post — diff compiled vs decompiled before publishing so you don't silently change ads/CTAs the operator didn't ask to touch. Rebuild missing paragraphs/features from fresh research (Directive 1), don't render the stub as-is. Change content via `wp_post action=update`, NOT `wp search-replace`. Infra breakage (imgproxy/CSP/mu-plugin) → REPORT, out of scope.

## Reporting contract (final message — prose, every run)
1. Post(s) touched (id, title, draft URL) + `workflow_id` if a workflow ran. 2. What changed (places rewritten/added/replaced, images swapped, SEO/tags). 3. Audit status (`wp_audit_article` errors = 0, or exact remaining + why blocked). 4. Flagged for operator (refused enrich matches, places with empty fields + which/why, closed venues replaced, infra breakage, anything denied). 5. Data corrections (old → new). 6. Provenance spot-list (the 3 most consequential facts — source + literal value). **End with the explicit handoff line: «Черновик готов, ждёт публикации оператором» — never claim the post is live.**

## Workflow runs (`wf_create`)
When your task says to run a workflow: `wf_create template=create-collection|create-events|update-collection …` — the workflow is owned by YOUR identity and its tool steps execute as you. Self-approve steps UP TO `create-draft`/`pending-update`; the engine then parks at an approval gate your token cannot pass (`go-live` / live `update`) — that parked state IS your deliverable. Emit the reporting contract with the `workflow_id` and stop: do not poll, nudge, or retry the gated approval.
